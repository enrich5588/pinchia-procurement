# 電子簽呈規格(目標:取代正式版)

> Leo 2026-08-21 裁定:齊軒的電子簽呈以**取代正式版**為目標。
> 這份規格描述正式版的行為與資料形狀;你的版本必須先達成同等語意,
> 再談改進。**終局整合方式=概念與程式重寫進主 repo 走雙人審查**,
> 不是直接合併你的 code —— 所以「跟規格對齊」比「寫得快」重要。

## 0. 法律紅線(最重要,先讀)

簽呈依公司經營管理手冊**第八章**具正式效力:
- 已核定(approved)的簽呈**不可就地修改**;要改=開新簽呈以 supersedes 指向舊單。
- 退回**不是終態**(回 draft 改完重送);終結用 void,理由必填。
  狀態機沒有 rejected。
- 每一個動作都進不可刪的 SignoffLog(誰/何時/做了什麼/理由)。
- **取代上線時,既有簽呈資料與稽核軌跡必須無損遷移**,管制編號連續性不可斷。
  這是取代案的第一驗收項,不是最後一項。

## 1. 資料形狀(欄位語意,非逐字 schema)

- **Signoff(主檔)**:管制編號(民國年+四碼流水,**送出才給號**,draft 不佔號,
  unique 防撞)/承辦日期/承辦單位/承辦人/主旨/說明/預期效益/擬辦/案件類別/
  重大性(一般行政|重大 →應提董事會旗標+決議文號)/幣別+金額+計費方式
  (一次|按月|按年)+合約期間(月)+匯率+**換算新台幣總額 amount_twd**/
  速別(普通|急件)/密級(普通|密件)/status/版次 version。
- **SignoffStep(簽核關卡)**:簽呈+版次/關卡序 stage_no/關內序 seq/
  角色(ApprovalRole)/種類/指派人 assignee+候選人 candidates/狀態。
  退回重送=版次+1,整條鏈重建(舊版關卡留檔可稽核)。
- **SignoffAttachment/SignoffLog**:附件與全動作稽核流水。
- **ApprovalRole/ApprovalRoleMember/ApprovalRule**:角色/角色成員/
  簽核規則表。

## 2. 級距與簽核鏈(最容易寫錯的部分)

1. **級距是資料不是程式碼**:金額門檻與簽核鏈全在 ApprovalRule 表,
   改門檻=改資料,不改程式、不重新部署。
2. **級距判定唯一依據=amount_twd(合約總額)**,不是月費 ——
   防拆單規避(USD 600/月×24 月要用總額判,算法寫死不給選項)。
3. 鏈的組成:重大性決定 base 鏈(第八章);一般行政用金額級距鏈(第六章);
   兩者聯集成單一鏈,順序照規則宣告不重排。
4. 明細頁要顯示**級距算式**——使用者要看得到「為什麼走到這個層級」,
   不是只看到結果。

## 3. 頁面(正式版現有)

清單(自己的+待我簽的)/建立/明細(含簽核動作)/編輯(draft only)/
簽核角色管理頁(管理員)。權限見 docs/PERMISSIONS.md;簽核動作只有
「該關卡當前 assignee 或候選人」能按,管理員不代簽(要代簽走改派+留 log)。

## 4. 取代案驗收 gate(依序,一關不過不進下一關)

1. 行為對齊:上述語意全數通過測試(含三身分×每閘門、狀態機反例、
   拆單反例、版次重建)。
2. 遷移演練:dev 環境以正式資料快照跑遷移,簽呈數/步驟數/log 數/
   管制編號逐一對帳=0 diff。
3. 概念移植主 repo → 小歐+小居雙審(歷史經驗:五到十輪是常態,
   每輪 finding 都是真的,修完會更強)。
4. Leo 核准 → 灰度(Develop 管理員先行)→ 全員。

## 5. 給齊軒的起步建議

- 先做狀態機+級距引擎+測試(核心語意),再做頁面 —— 反過來會把語意
  寫散在 view 裡。
- 級距引擎寫成純函式(輸入金額與規則表、輸出鏈),可獨測。
- 每個「不可以」都寫一條反例測試:approved 改內容、draft 給號、
  月費判級距、主管開管理頁 —— 抓得住才算有這條規則。

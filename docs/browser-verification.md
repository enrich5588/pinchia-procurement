# 瀏覽器移植驗證紀錄

日期：2026-11-09。使用新 `.venv-rebuild` 啟動 Django，透過實際瀏覽器逐頁檢查與操作；主站保留於 http://127.0.0.1:8000/ 。

## 環境隔離

- 主站 `8000` 沿用原 `db.sqlite3` 與 `private-media/`。
- 驗證站 `8001` 使用 `.rebuild-verification/browser.sqlite3` 與 `.rebuild-verification/browser-media/`。所有新增、送簽、核准、取消及匯入操作皆發生在驗證站。
- 驗證角色包含一般同仁 `staff1`、管理部 `manager1`、簽核人 `wang` 與超級使用者 `admin`。
- 兩個伺服器均在背景運行並啟用 Django 開發模式自動重載。

## 實際瀏覽器操作

| 功能 | 已操作並確認結果 |
| --- | --- |
| 登入／首頁／登出 | 一般同仁、管理部、簽核人及管理員登入；登入後導航；POST 登出回到專案登入頁 |
| 用品申請 | 新增兩個品項、送出、清單統計更新、查看彈窗、修改數量並重新送出；管理部勾選批量處理、單筆完成並結案 |
| 設備申請 | 新增與送出；管理部轉發至資訊部，原設備申請同步改為處理中 |
| 協作案件 | 管理部轉發後查看清單；承接部門開啟詳情、查看來源內容、設為處理中與完成 |
| 資產登記 | 新增、所屬部門與保管人選項、單價加營業稅即時計算、送出、查看；管理部指定財產編號並核准入冊 |
| 財產清冊 | 部門篩選後清單與統計同步、清除條件、點列開啟詳情、編輯廠牌並儲存、直接新增公司財產、重複財產編號提示 |
| 財產異動 | 同仁申請修改、帶入原欄位及既有圖片、送出異動申請；使用站內確認視窗取消並確認結案 |
| 財產 Excel 匯入 | 瀏覽器開啟上傳說明頁；實際後端上傳產生預覽後，在瀏覽器修改財產名稱、確認匯入，清冊顯示修改後結果 |
| 資產登記 Excel 匯入 | 實際後端上傳產生預覽後，在瀏覽器檢視與確認送出，清單新增待審核申請 |
| 圖片 | 實際後端上傳圖片後，在瀏覽器開啟財產詳情，確認圖片數量與圖片載入成功（naturalWidth = 320） |
| 數位簽呈 | 建立、送出、查看、簽核人退回並填意見、申請人修改重送、簽核人核准；歷程保留兩次送簽與各次意見 |
| 資料庫監看 | 頁面載入、搜尋資料表、關閉自動更新、展開 assets_asset 完整資料；未在此頁修改資料 |
| 管理後台 | 超級使用者登入管理站，確認業務模組及「組織與帳號」的部門、使用者部門模型均可列出 |

另逐頁開啟用品、設備、資產登記、簽呈的新增與詳情獨立頁面版本，以及協作與財產詳情，共十個獨立表單／詳情頁，確認可渲染且沒有 Django 錯誤頁。

## 版面檢查

六個主要清單頁（用品、設備、財產、登記、協作、簽核）分別在桌面 `1280 × 800` 與手機 `390 × 844` 檢查。各頁沒有整頁橫向溢出；大型清冊在桌面由表格容器捲動，在手機改為既有卡片版面。資產長表單的手機版另檢查彈窗外框不捲動、內容區可捲動，沒有第二層彈窗捲軸。

檢查結束已還原暫時的瀏覽器 viewport 設定。畫面紀錄在本機 `.rebuild-verification/screenshots/`（不進版控）。

## 發現與修正

1. **全新示範環境無法送簽**：初始化未建立固定簽核路徑需要的 wang／kao／gardine／hu。`seed_demo` 現在會建立缺少的開發簽核帳號；保留既有帳號的密碼與啟用狀態。新增反例測試並覆蓋所有金額級距的送簽路徑。示範帳號僅在明確執行示範資料命令時建立，未套用到主站資料庫。
2. **登出誤入 Django 管理站**：設定 `LOGOUT_REDIRECT_URL`，登出後回到專案登入頁。測試確認 GET 無法登出、POST 會清除登入狀態並正確跳轉。
3. **資產長表單雙重捲軸**：彈窗外框禁止溢出捲動，內層採用 border-box 計算含 padding 的最大高度；更新樣式版本避免快取舊 CSS。桌面與手機均重新驗證。
4. **首頁殘留開發替身說明**：移除原始碼檔案位置及 superuser 技術提示，改為實際可使用的功能導航說明。

## 驗證結果與範圍限制

- 完整回歸測試 **179 項全部通過**。
- Django 系統檢查、`makemigrations --check --dry-run`、`git diff --check` 通過。
- 六個主要清單頁桌面／手機版與十個表單／詳情獨立頁均已實際開啟；上述流程完成後讀取瀏覽器錯誤／警告紀錄，沒有紀錄。
- 瀏覽器檔案選擇工具曾失去連線，本機視窗備援亦授權逾時，因此**原生選檔步驟未完成瀏覽器端驗證**。圖片與 Excel 上傳改由 Django 實際 view 接收 multipart 檔案，之後的圖片顯示、預覽編輯與確認匯入仍在瀏覽器操作；檔案大小、格式、權限、匯入錯誤與回滾等由現有後端回歸測試覆蓋。
- 本次沒有對每一種角色 × 每一個狀態組合做瀏覽器排列測試；其權限與狀態反例以完整回歸測試補足。未對外部署。

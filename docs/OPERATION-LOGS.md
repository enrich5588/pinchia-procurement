# 操作紀錄與保存期限

系統管理員可從「系統管理 → 操作紀錄」（`/operation-logs/`）搜尋操作者、資料名稱／編號、模型或路徑，依操作類型篩選，每頁 20 筆，展開查看修改前後值與關聯編號。一般員工、部門管理者及僅有 is_staff 的帳號無法查看；Django 管理後台亦僅允許唯讀查閱。

## 記錄範圍

- 網站的頁面查閱、送出、下載／匯出、拒絕存取及錯誤回應，記錄時間、HTTP 方法、路徑、路由、結果與操作者。靜態圖片／CSS／JS 及專用健康檢查路徑除外。
- 辦公用品、設備、資產、資產登記、圖片與檔案關聯、協作、簽呈及簽核步驟的新增、修改及刪除，記錄資料編號與欄位前後值。
- 部門、員工帳號、M365 身分、所屬部門、部門主管、權限規則、面板狀態、使用者群組／權限關聯。
- 登入、登出及登入失敗。M365 登入中的資料同步，會在驗證成功後對應至同一登入人員，並以關聯編號串起該次操作。
- 背景 M365 同步記錄來源與同步結果；系統背景作業使用「系統／背景作業」身分，不冒用某位員工。命令列直接執行模型異動以「系統／命令列」標示，無法憑空識別實際的公司使用者。

資料儲存在同一個持久化資料庫的 `platform_stub_operationlog`。修改與其稽核紀錄在同一交易內，失敗回滾不留下成功修改紀錄；請求結果另外記錄。記錄失敗會使對應的業務寫入失敗，不允許無紀錄地完成修改。匯出只保留請求資訊，不另複製匯出檔；附件只記錄檔名／儲存路徑及關聯，不保留被刪除的檔案內容。

不記錄 HTTP request body、query string、Cookie、Session、Authorization header、密碼內容或雜湊、M365 權杖與憑證私鑰。密碼異動僅記錄「密碼已變更」。匯入預覽的 rows／skipped 暫存內容不複製到 LOG；正式匯入後每筆業務資料的結果有獨立紀錄。其他正常業務欄位（含備註、簽核意見）依原值記錄，勿將金鑰貼入業務欄位。

## 保存 30 天

一個月在此採最近 **30 天**。查詢頁立即排除超過 30 天的資料，獨立背景 worker 每小時刪除逾期操作紀錄、既有 PermissionAudit 及 Django LogEntry；實體清除最多有一個小時的排程差。業務案件、人員、附件及當前權限／面板設定不會被清理。

```powershell
# 立即清理一次
./.venv-rebuild/Scripts/python.exe manage.py maintain_operation_logs
# 持續執行，每小時清理
./.venv-rebuild/Scripts/python.exe manage.py maintain_operation_logs --watch
```

本機 `scripts/dev.ps1` 會隨網站啟動清理 worker，結束時一併停止。直接執行 runserver 時須另外啟動 worker。正式 Compose 已新增 audit_cleanup 服務，共用 `/data/db.sqlite3`；部署會停止清理 worker 後備份，再 migrate、清理及啟動所有服務。其他 Server 架構請用服務管理器監督上述 worker，設定開機啟動與失敗重啟。

重新部署不會重建 LOG 資料表；還原舊備份後仍會套用目前的 30 天查詢與清理規則。**資料庫備份是獨立的保存範圍**，既有備份可能含較早紀錄，本清理不會刪除整份備份；如備份也須嚴格保留一個月，需另外設定備份保留政策。

啟用前只有既有權限／面板紀錄可移轉，未曾記錄的舊操作無法回溯補建。LOG 的讀取與修改嘗試也會被記錄。一般管理介面無法修改或刪除 LOG；具有資料庫／Server 完整權限的人仍能直接操作資料庫，因此這不是對資料庫管理者防竄改的外部稽核系統。

## 開發維護

業務與組織模型繼承 AuditedModel，save／delete 訊號及自訂 QuerySet 的 update／bulk_create／bulk_update 會記錄。bulk_create 的 silent conflict/upsert 選項不允許，應明確新增或更新。新增業務模型請沿用 AuditedModel。原生 SQL、繞過 ORM 的外部工具、未納入的第三方資料表與直接檔案操作不會自動記錄；不能用這些路徑處理網站業務寫入。模型變更的欄位以實際儲存結果為準，未儲存欄位不會誤記。不可記錄敏感認證資料。

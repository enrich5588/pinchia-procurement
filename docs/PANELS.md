# 面板管理

系統管理員從「系統管理 → 面板管理」（`/panels/`）控制辦公用品申請、設備申請、財產清冊、資產登記、協作案件及數位簽呈，共六個板塊。

| 狀態 | 一般同仁 | 系統管理員 |
| --- | --- | --- |
| 開發中 | 隱藏入口，拒絕直接存取 | 可進入驗證 |
| 已完成・暫不開放 | 隱藏入口，拒絕直接存取 | 可進入驗證 |
| 已完成・已開放 | 依既有部門／個人權限使用 | 可進入 |

「開放」僅指已登入的公司同仁，不會開放匿名登入或將系統發布至網際網路。完成狀態由管理員判斷並設定，系統不會自動宣告功能開發完成。

變更狀態後按「儲存面板設定」，於後續請求立即生效，無須重新登入或重新啟動。首頁資料、側欄、行動捷徑與直接 GET／POST 進入均受控；個人明確允許及管理部門授權無法越過未開放面板。既有案件、附件、部門與個人權限不會因此刪除或改寫；重新開放時沿用原規則。系統管理員持續可使用面板管理與權限管理，以免鎖住維護入口。

既有 `.env` 的 `FEATURE_OPEN_TO_ALL=false` 仍為全站總開關，會蓋過個別面板開放狀態；面板管理頁會顯示提示。預設 true 時以個別面板狀態控制。資料庫監看及其他系統管理工具維持原本權限，未列入這六個業務面板。

六個板塊預設均為「開發中」，由系統管理員確認後再逐一開放。升級時，尚未人工調整的舊版「已開放」初始狀態會改為「開發中」；已有設定人員或面板異動紀錄的狀態會保留。新增面板資料亦預設為開發中；缺少資料的面板會拒絕一般使用者存取。執行 `python manage.py migrate` 後生效。

頁面僅允許啟用中的超級使用者維護，儲存採 POST、CSRF 與同一交易更新。每個異動記錄在既有 `PermissionAudit`（target_type=`panel`），包含操作者、時間、面板及前後狀態，頁面顯示最近 20 筆。版本檢查會拒絕覆蓋其他管理員已儲存的變更。程式應使用 `organization.panel_views.save_panels` 寫入；直接 SQL 不會產生異動紀錄。
